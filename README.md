# MangaSee

A private manga reading room for iPad and desktop. React PWA + Fastify/SQLite + Komga. Organize virtual series without moving the files in your library folders.

## Try the demo

```sh
npm ci
npm run demo
```

Open **http://localhost:3000** and sign in with **mangasee-demo**. This preview binds only to loopback, uses original generated fixtures, and stores its catalog separately in `data/demo.sqlite`. It never connects to your real library.

## Run locally

Requires Node **24 or newer** (SQLite is built into Node). No external database is needed.

```sh
cp .env.example .env
# Edit APP_PASSWORD in .env (12+ characters).
npm ci
npm run dev
```

Open **http://localhost:5173**, using exactly that hostname because cookie/origin validation is intentional. The example configuration enables clearly labeled **demo mode** with 12 original generated image fixtures. They exercise reader interaction, not real archive extraction. Set `DEMO_MODE=false` and configure Komga to read real books.

To exercise installation/offline mode, use the production build:

```sh
npm run build
# Change APP_ORIGIN in .env to http://localhost:3000 first.
npm start
```

Service workers run in the production build on localhost or trusted HTTPS. After the first visit, reopen/reload the app once before testing offline startup. Do not use the Vite development server for offline acceptance tests.

## Included

- Personal password login; HTTP-only sessions; same-origin write requests.
- Paginated library, search, format/read-status filters, continue reading, and unavailable books.
- Virtual series across folders; manual ordering; collections; editable labels; missing-book relinking.
- Image reader for Komga-rendered CBZ/CBR/PDF pages: RTL/LTR, single/double/vertical modes, spread offset, zoom, page navigation, next volume, and bounded preloading.
- Versioned progress with explicit device-conflict resolution and offline buffering.
- Foreground offline downloads with pause/resume, removal, cache verification, and quota errors.
- EPUB.js reader with table of contents, text size, themes, fixed/reflow layouts, location progress, and offline files. Publication scripts are disabled; CSP blocks remote resources.
- Compose and automated Proxmox LXC deployment, read-only library folders, Caddy HTTPS, local databases, and backup/update scripts.

For an already running server, follow [updating an existing installation](docs/updating.md), including runtime requirements and refreshing the tablet PWA.

See [automated Proxmox LXC deployment](docs/proxmox-lxc.md), [VM/Compose deployment](docs/deployment.md), [architecture and API](docs/architecture.md), and [milestone acceptance record](docs/milestones.md).

## Checks

```sh
npm run test:deploy     # local LXC installer guards and update recovery tests
npm run check           # integration/unit tests + type checks + production build
npx playwright install chromium webkit
npm run test:e2e        # browser tests against an isolated demo server
npm run format:check
```

Browser tests use a temporary in-memory catalog. EPUB fixtures are original test content generated by `python3 scripts/generate-fixtures.py`; they deliberately include a remote image and script to verify isolation. Do not treat the test fixture renderer as evidence of Komga format compatibility: real CBZ/CBR/PDF acceptance requires your running Komga and sample library.

## Release status

This is an implementation for local evaluation, **not a certified v1.0 deployment**. Hardware/infrastructure milestone gates remain open: trusted HTTPS on your iPad, real library/Komga files, the 30-minute reader session, device performance measurements, container restore rehearsal, and a week of normal use. Nothing has been deployed to your infrastructure from this workspace.
